## 附：固定 JSON 输出块（tracker.py 自动解析）

每次分析输出末尾必须附带以下 JSON 块（字段固定，缺失用 null）：

```json
{
  "match": "桑托斯 vs 弗拉门戈",
  "league": "巴甲",
  "market": "胜平负",
  "pick": "弗拉门戈胜",
  "prob": 0.54,
  "hedge": {"pick": "平", "prob": 0.23},
  "confidence": "中",
  "stake": 0,
  "market_odds": 1.80,
  "odds_snapshot_at": "2026-10-09T00:30:00+08:00",
  "lineup_status": "半成品",
  "dan_single_available": false,
  "analyzed_at": "2026-10-09T00:35:00+08:00",
  "model_version": "penaltyblog-1.13.1/dixon-coles",
  "data_date": "2026-10-09",
  "closing_odds": null
}
```

字段说明：
- `market`：胜平负 / 大小球 / 让球
- `lineup_status`：只能是"成品"或"半成品"
- `dan_single_available`：该场赔率表有无红色"单"标识（true=可胜平负单关，false=仅可串关）；下注建议前必须识别
- `closing_odds`：赛后由 settle.py 回填收盘赔率（市场平均 Avg 列），用于 CLV 计算
- 解析命令：`python scripts/tracker.py add-from-json analysis.json`

## 附：复盘格式（每日上午校准回填时用，2026-11-09 新规）
每场错单定性三选一 + 一句话证据，写入当日汇报与 `~/memory/YYYY-MM-DD.md`，同时结算台账 `~/workspace/goals/goal-2/files/足彩投注台账.xlsx`（「建议核实」填赛果/红黑/盈亏，「日汇总」更新实际投入/实际盈亏/本金/ROI；本金只随用户确认下注的票变动）：
- 冷门：模型方向与市场一致、概率占优但结果反向（方差），如"主胜 65% 被 0-0，xG 占优但临门一脚差"
- 方向错误：模型主方向本身错判，如"客胜 55% 但主队全场压制，模型低估主队主场"
- 信息缺失：赛前未掌握的关键信息，如"首发门将赛前热身受伤、核心中场红牌停赛未入名单"
红单不写复盘，只记命中。
